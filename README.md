# 静读 · NovelReader

> 鸿蒙原生（HarmonyOS NEXT / ArkTS）完全离线的本地 TXT 小说阅读器。
> 零联网 · 零广告 · 零账号 · 进度绝不丢。

An offline-first TXT novel reader for HarmonyOS NEXT, built with ArkTS / ArkUI.
No network, no ads, no accounts — all data stays in the app sandbox.

## 为什么做这个

手机里存了十几年的 TXT 小说，市面上的阅读器普遍有三种毛病：开屏和章节间插广告、不给权限不让读、把阅读偏好上传做画像。另有两个纯技术痛点：**GBK/GB18030 编码一打开就是乱码**，**十几 MB 的单本长篇整读进内存，打开即卡死**。

静读只做一件事：**读你自己的书**。它不联网（不是"可以离线"，是工程里没有任何网络请求代码），不申请任何敏感权限（文件一律经系统文件选择器授权），所有数据留在应用沙箱，卸载即彻底删除。

## 几个值得一提的设计

- **不存页码，存偏移。** 进度 = 章节序号 + 章内 UTF-16 偏移 + 百分比。页码会随字号/行距/屏幕宽度全部失效，偏移不会。这也是书签、划线、笔记与进度共用同一套坐标的原因。
- **大文件按字节偏移寻址。** 导入时以 1 MiB 分块流式解码，分章只记录每章的**字节区间**；阅读时按偏移随机读单章（单章解码上限 2 MiB + LRU 缓存）。内存占用与书的大小无关。
- **分页结果按排版指纹缓存。** `layoutKey` = 宽/高/字号/行距/字距/边距/字体/算法版本号，切回同一章不重算，改排版才失效。
- **分页测量与渲染强制同源。** 字体解析收敛到唯一入口 `resolveFontFamily()`，测量宽度与渲染宽度取同一个 `measureWidth()`——避免"量的是 A、画的是 B"导致页尾被裁（这类 bug 不报错，只表现为"有时少一行"）。
- **可疑分章主动预警。** 从"平均每章字数"反推编码选错的特征，在入库前拦住，而不是让用户打开后白屏假死。

## 工程结构

```
entry/src/main/ets/
├── pages/         @Entry 页面（启动 / 根 / 书架内嵌 / 导入确认 / 阅读 / 目录 / 分组 ×2 / 详情 / 自检）
├── views/         可复用 @Component（bookshelf / reader / stats / common）
├── viewmodels/    状态与业务编排（书架 / 阅读 / 刷新注册表 / 跳章交接）
├── data/
│   ├── repository/ 唯一允许写 SQL 的一层（6 个）
│   ├── service/    流程与算法，不碰 SQL（导入 / 分页 / 进度 / 统计 / 设置 / 备份 / 阅读 / 搜索）
│   └── source/     字节源抽象（ByteSource / RawFileSource / FilePickerSource）
├── model/         纯数据结构
└── common/        常量 / 工具（编码探测 / 分章 / 流式解码 / 哈希）/ 主题令牌
```

分层依赖只能向下：`pages`/`views` → `viewmodels` → `service`/`repository` → `database`。View 不碰 `relationalStore`/`fs`/`preferences`，Repository 不返回 `ResultSet`。

存储：**RelationalStore（SQLite，6 张表）+ Preferences + 应用沙箱文件**。表结构、索引、迁移策略与全部踩坑记录见 [设计文档](docs/小说阅读器设计文档.md)。

## 构建

环境：**DevEco Studio** + **HarmonyOS SDK 6.0.2(22)**（`compatibleSdkVersion` 6.0.1(21) / `targetSdkVersion` 6.0.2(22)），`modelVersion` 6.0.2。

```bash
# 1. 用 DevEco Studio 打开工程根目录
# 2. 同步依赖（仅测试框架）
ohpm install
# 3. Project Structure → Signing Configs 勾选自动签名
# 4. Run 'entry'
```

工程无 `signingConfigs`（签名信息属个人环境，不入库）；`deviceTypes` 目前只声明 `phone`。

## 已知限制

诚实清单，欢迎 PR：

- **仿真翻页（cover）** 未实现，设置面板只提供滚动 / 左右翻页 / 平移翻页三种，不做"选了没反应"的假选项。
- **TTS 朗读** 只有设置字段预留，没有语音引擎与入口。
- **服务卡片「继续阅读」** 未实现。
- **平板 / 折叠屏** 未适配（`deviceTypes` 仅 `phone`）。
- **大文件导入仍占用主线程**：10 MB+ 会有秒级停顿（有进度文案兜底），彻底方案是把解析放进 `taskpool`。
- **分组只有创建/重命名/删除，没有手动排序 UI**（按创建顺序排列）。
- **字体切换** 字段已贯通渲染与分页，但设置面板尚未开放入口。
- **自动化测试** 仅有 DevEco 模板，真正承担回归的是内置自检页：页面 `pages/SelfCheckPage` 仍在路由表中，但「我的」页的入口已移除，需要时在任意页面临时 `pushUrl` 即可进入。
- **仅支持 TXT**：EPUB 评估后明确放弃（目标用户的书源天然是 TXT）。

## 隐私

不联网、不采集、无账号、无第三方统计 SDK、无任何敏感权限。书籍、进度、标注、统计全部存于应用沙箱；备份文件由用户自己选择保存位置并自行保管；卸载即彻底删除。
